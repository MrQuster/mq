# Чеклист проверки MQ Launcher на Windows 10 / 11

Краткое руководство для проверки сборки `mq.exe` на Windows (x86_64).

## Расположение файлов и журналов

По умолчанию MQ использует стандартные каталоги профиля Windows (если рядом с `mq.exe` нет файла `portable.flag`):

- Данные, инстансы, CAS и ассеты: `%LOCALAPPDATA%\MQ\` (`C:\Users\<Имя>\AppData\Local\MQ\`)
- Журналы аварий (`crash-*.log`, `crash-latest.log`): `%LOCALAPPDATA%\MQ\logs\`
- Журнал состояния активной установки: `%LOCALAPPDATA%\MQ\install.journal`
- Конфигурация (`config.toml`, `theme.toml`): `%APPDATA%\MQ\` (`C:\Users\<Имя>\AppData\Roaming\MQ\`)

Быстро открыть каталог данных можно через `Win + R` -> `%LOCALAPPDATA%\MQ`.

## Пошаговая проверка (6 шагов)

### 1. Запуск бинарного файла и проверка рендерера
1. Распакуйте архив `mq-portable-windows-x86_64.zip` или запустите установщик `mq-windows-x86_64-setup.exe`.
2. Запустите `mq.exe` двойным кликом из Проводника.
3. Убедитесь, что главное окно открывается без консольного окна на фоне, шрифты с кириллицей отображаются корректно, переключение вкладок работает без задержек.
4. При проверке из PowerShell выполните:
   ```powershell
   .\mq.exe --version
   ```

### 2. Предварительная диагностика (`mq doctor`)
Откройте PowerShell в папке с `mq.exe` и выполните проверку окружения и доступности серверов:
```powershell
.\mq.exe doctor --install 1.21.1
.\mq.exe doctor --install 1.20.1 --loader fabric
```
Все этапы (манифест, `version.json`, Java, `client.jar`, библиотеки, нативные `.dll`, ассеты) должны завершиться со статусом `[OK]` или `[WARN]`.

### 3. Установка актуальной версии (Vanilla) через GUI
1. В разделе «Инстансы» нажмите «Создать инстанс».
2. Выберите актуальную релизную версию (например, `26.3` или `1.21.4`), загрузчик `Vanilla`, нажмите «Создать».
3. Нажмите «Установить» и дождитесь завершения всех этапов (`Манифест версии` -> `Игровые ресурсы` -> `Финализация`).
4. Убедитесь, что окно лаунчера остаётся отзывчивым во время скачивания 3000–5000 файлов ассетов и переходит в статус «Установлено».

### 4. Установка версии 1.20.1 (Fabric) и проверка отмены
1. Создайте второй инстанс с версией `1.20.1` и загрузчиком `Fabric`.
2. Запустите установку, через 3–5 секунд нажмите «Отменить», затем повторно нажмите «Установить» и дождитесь завершения.
3. Проверьте целостность файлов через CLI:
   ```powershell
   .\mq.exe verify "1.20.1 Fabric"
   ```

### 5. Проверка сухого (`--dry-run`) и реального запуска игры
1. Выполните сухой запуск из PowerShell, чтобы убедиться в корректной сборке аргументов JVM и путей с разделителем `;`:
   ```powershell
   .\mq.exe launch "1.20.1 Fabric" --dry-run
   ```
2. В графическом интерфейсе нажмите «Играть» на установленном инстансе.
3. Убедитесь, что процесс `javaw.exe` / `java.exe` запускается, окно Minecraft открывается со звуком и русским языком интерфейса (`ru_ru`).

### 6. Проверка восстановления после нештатного завершения
1. Если процесс установки был принудительно прерван (или завершился с ошибкой), при следующем запуске `mq.exe` должно появиться диалоговое окно восстановления с указанием версии и этапа, на котором прервалась установка.
2. Проверьте работу кнопки «Скопировать диагностику» — в буфер обмена должен скопироваться отчёт без токенов и личных путей профиля.

## Что прислать при обнаружении сбоя

Если установка или запуск завершились ошибкой или вылетом:

1. Выполните в PowerShell экспорт обезличенного отчёта диагностики:
   ```powershell
   .\mq.exe doctor --install <версия> --export > doctor-report.md
   ```
2. Приложите файлы из каталога `%LOCALAPPDATA%\MQ\`:
   - `%LOCALAPPDATA%\MQ\logs\crash-latest.log` (если файл создан)
   - `%LOCALAPPDATA%\MQ\install.journal` (если файл присутствует)
   - `doctor-report.md`
3. Укажите версию Windows (`winver`), модель видеокарты и установленный антивирус (Windows Defender или сторонний).
